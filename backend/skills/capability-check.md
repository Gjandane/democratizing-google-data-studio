# Capability check

1. Retain original source meaning and all explicit behaviors, with exact source IDs.
2. Suggest capability IDs and data mappings; code alone classifies support using dated evidence.
3. Preserve metric unit, aggregation and grain. Missing or ambiguous definitions require clarification.
4. Unknown behavior stays unknown. Never disguise animation as a static geo_map or use screenshot
   pixels as a replacement for interactive components.
5. Never infer consent, mark requirements resolved, or drop existing requirements.
